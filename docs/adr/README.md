# Architecture Decision Records

ADRs record durable architectural choices and their trade-offs. Create an ADR before implementing a material change to module boundaries, persistence, messaging, runtime topology, deployment platform, or trust model.

Use the structure below. Status values may include `Proposed`, `Accepted`, `Superseded`, or `Rejected`. Dates use `YYYY-MM-DD`. Never erase an accepted decision; add a superseding ADR and link both records.

```markdown
# Title

Status:
Date:

## Context

## Options considered

## Decision

## Consequences

## When to revisit
```
